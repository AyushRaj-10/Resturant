# Restaurant Order Management System (OMS)

A production-grade Restaurant Order Management System demonstrating the safe integration of Generative AI and Autonomous Multi-Agent AI with guarded tool calls. Built with FastAPI, SQLAlchemy 2.x, MySQL, and a vanilla JavaScript frontend, the application enforces a strict architectural boundary: Large Language Models (LLMs) are permitted to draft text and suggest actions freely, but any autonomous database mutation or tool execution must pass through strict Pydantic validation, a multi-stage deterministic Python security guard, mandatory human-in-the-loop confirmation for destructive operations, and immutable audit logging.

---

## Key Features

### 1. Core Order Management
- **Menu Management**: Catalog of menu items with prices, descriptions, and real-time availability toggling.
- **Atomic Order Lifecycle**: State machine governing transitions: `PLACED` &rarr; `PREPARING` &rarr; `SERVED` &rarr; `PAID` (or `CANCELLED`).
- **Dynamic Billing**: Subtotal calculation with item price snapshotting (`price_at_order_time`), percentage-based discounts, and service charges with strict financial rounding.
- **Table Management & Filtering**: Orders filtered by table number and lifecycle status with allowed action introspection.

### 2. Generative AI (No Side Effects)
- **Bill Explanation**: Generates clear, friendly breakdowns of bills, item subtotals, discounts, and service charges.
- **Order Summary**: Conversational summaries of orders formatted for kitchen staff and diners.
- **Dish Recommendations & Upselling**: Context-aware recommendations based on current order selections.
- **Natural Language Draft Orders**: Converts diner free-text requests into structured order proposals without touching the database or saving orders until explicitly placed by human staff.
- **Deterministic Numerical Guard**: Re-validates that all currency values and percentages generated by the LLM match underlying database totals before serving responses to users.

### 3. Agentic AI (Multi-Agent System)
- **Specialist Personas**: 
  - **Router Agent**: Analyzes intent and routes queries to specialists or answers menu questions directly.
  - **Order Specialist Agent**: Manages order creation and line-item quantity adjustments.
  - **Billing Specialist Agent**: Handles bill queries, discount applications, and payment summaries.
- **Autonomous Tool Calling**: Tools powered by the Groq API function calling protocol, strictly restricted to an allowlist per persona.
- **Session Memory**: In-memory multi-turn conversational context with sliding window turn caps.

### 4. Enterprise Safety & Guardrails
- **Deterministic Guard Layer**: 9 sequential Python rules evaluated with zero LLM dependence.
- **Human-in-the-Loop Confirmation**: Destructive operations (`cancel_order`, `delete_order`) produce cryptographically secure, single-use pending confirmation tokens that require human review.
- **Dual-State Validation**: Re-validates database state and business rules at both proposal time and confirmation execution time to prevent race conditions.
- **Provenance Verification**: Rejects sensitive operations unless targeted entity IDs were explicitly provided in the human prompt.
- **Fail-Closed Audit Log**: Invariant logging of all allowed, blocked, or pending tool calls into MySQL using an isolated database session.
- **Administrative Kill Switches**: Real-time environment flags to disable writes or destructive agent actions instantly.

## Quick Start

### Prerequisites
- Python 3.10+ (tested on Python 3.11)
- MySQL Server 8.0+ running locally on port 3306
- (Optional) Groq API key for AI features

### 1. Setup Virtual Environment & Dependencies
```bash
# Clone the repository
git clone <repository-url>
cd Resturant

# Create and activate virtual environment
python3 -m venv venv
source venv/bin/activate

# Install application dependencies
pip install -r backend/requirements.txt
```

### 2. Configure Environment Variables
```bash
cp .env.example .env
```
Update `.env` with your MySQL credentials and Groq API key (if available).

### 3. Initialize Database & Seed Menu
Ensure your MySQL database exists (e.g. `CREATE DATABASE restaurant_oms;`), then run:
```bash
# Initialize database tables
python3 backend/scripts/init_db.py

# Populate initial menu items (idempotent)
python3 backend/scripts/seed_menu.py
```

### 4. Run the Backend API Server
```bash
# Start FastAPI backend at http://localhost:8000
PYTHONPATH=backend uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```
Interactive OpenAPI documentation will be available at: `http://localhost:8000/docs`.

### 5. Serve the Frontend Client
In a separate terminal window:
```bash
# Serve static frontend files on port 3000
python3 -m http.server 3000 --directory frontend
```
Open your browser and navigate to: **`http://localhost:3000`**.

## Running Without an LLM (Fallback Mode)

When `LLM_PROVIDER=none` or when `LLM_API_KEY` is not provided, the system remains **100% operational**:
- **Full Order Management**: Creation, line-item adjustments, status progression, billing, and cancellations function identically.
- **Deterministic Generation Fallbacks**: 
  - `/ai/orders/{id}/bill-explanation`: Produces an exact, formatted text breakdown directly from DB totals.
  - `/ai/orders/{id}/summary`: Produces a standard itemized kitchen/diner summary.
  - `/ai/orders/{id}/suggestions`: Recommends top-rated menu items not currently in the order.
  - `/ai/draft-order`: Utilizes an exact regex and keyword parser to match items from the menu catalog.
- **Agent Chat Panel**: Returns a clear system notification explaining that the live AI assistant is offline and prompts staff to use the standard UI controls.
